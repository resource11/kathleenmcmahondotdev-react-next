## Context

O'Reilly Media's internal product teams were building across a fragmented surface: a learning platform serving millions of users, maintained by over a dozen teams, with no shared component primitives, no theming system, and documentation scattered across disparate sources. The ORM Design System was the effort to change that.

## My Role

I joined as a Frontend Engineer in February 2018 and moved into a Tech Lead role in April 2019. My role was hands-on across the full system lifecycle: component architecture, accessibility implementation, documentation infrastructure, and the contribution model that helped other teams adopt the system.

Collaborators included Paul Bouchon, Martin Bravo, Rune Madsen, Pasha Craydon, and Phil Skaroulis.

---

## Challenge

The design system had to solve three problems simultaneously:

- **No shared accessible primitives** — product teams were building their own components, inconsistently, with varying accessibility standards
- **No theming system** — surface-level visual changes required manual updates across every app
- **Fragmented documentation** — teams couldn't self-serve reliably; the docs experience didn't reflect what had actually shipped

The challenge was design-engineering, not product design: the system itself was the product, and it had to work for the teams building with it.

---

## Approach

### Accessible React component library

Built reusable, accessible React components using Storybook and Component-Driven Development. Accessibility was a design constraint from the start — ARIA roles, keyboard interactions, and color contrast were part of the component spec, not an audit step after the fact.

<Figure
  src="placeholder/orm-storybook-component-gallery"
  alt="Storybook component index showing the ORM design system component gallery"

### Design token CSS architecture

Designed a CSS custom properties architecture to enable consistent theming across 12 teams and 20+ applications. Token-driven theming meant product teams could apply brand updates without touching component internals.

<Figure
  src="placeholder/orm-token-architecture"
  alt="Design token CSS architecture diagram showing token structure and theming layers"
  caption="Token structure enabling theming across the platform."
/>

### Gatsby documentation site

Replaced the prior docs experience with a Gatsby-based site integrating MDX files, JSDoc-generated API documentation, NPM package references, and explicit accessibility and design guidelines. The docs were authored and maintained alongside the components, not as an afterthought.

The Gatsby docs POC was work I built; it was merged by Pauline Lai. This work is a candidate for a standalone deep dive.

<Figure
  src="placeholder/orm-gatsby-docs-site"
  alt="ORM design system Gatsby documentation site showing component detail page with accessibility guidelines"
  caption="Gatsby docs site — component documentation with accessibility guidelines."
/>

### Contribution model

Defined contribution guidelines, maintained CI/CD processes, and ran office hours and pairing sessions to reduce adoption friction for consuming teams. The model made it possible for product engineers to contribute components back to the system without requiring design system team involvement for every PR.

<Figure
  src="placeholder/orm-contribution-guidelines"
  alt="ORM design system contribution guidelines documentation page"
  caption="Contribution guidelines — making the system something teams could give back to."
/>

### Accessibility workshops

Led workshops on inclusive design and accessibility for designers, engineers, and content stakeholders across O'Reilly. These weren't one-time events — they were part of raising the baseline for everyone building on the platform.

## Reflections

This engagement predates the widespread adoption of design token tooling and modern a11y testing infrastructure. Given the same scope today, I'd introduce automated accessibility regression testing earlier and lean harder into token-first architecture from day one rather than retrofitting it. The contribution model also needed more explicit governance — office hours scaled the intent but didn't fully replace the need for clearer ownership signals.
